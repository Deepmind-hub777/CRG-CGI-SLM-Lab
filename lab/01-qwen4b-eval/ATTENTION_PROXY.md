# Qwen3-4B 注意力代理实验

**日期：** 2026-11-26  
**目的：** 看锚定卡是否真的改变模型注意力，而不是只改输出格式。  
**方法：** 不直接导出 attention map；用“锚定内容翻转 / 位置变化 / 重复”做行为代理。  
**样本：** E001（0 轴，多子句锚定）、E003（锚定能否自指，单规则锚定）。

---

## 1. 实验设计

| 条件 | 做法 |
|---|---|
| no_anchor | 不给锚定卡 |
| correct | 给正确锚定 |
| flipped | 把关键子句翻转（“权重之外”→“权重之内”；“不能”→“可以”） |
| repeat | 同一锚定重复两遍 |
| after_user | 把锚定卡从 system 移到 user 消息末尾 |

如果翻转关键子句后答案跟着翻，说明模型确实在看锚定内容；如果位置一变、答案用的子句也变，说明注意力有位置偏置。

---

## 2. 结果

### E001：多子句锚定

锚定原文：

> 0 = 坐标原点，定义语义空间；在权重之外；不是中间值、不是关断。

| 条件 | 输出 | 用了哪条子句 |
|---|---|---|
| no_anchor | “坐标系中起点或基准位置……零值或原点” | 无 |
| correct（system） | “语义空间的坐标原点，定义所有方向的基准” | 第 1 条 |
| flipped（system） | “语义空间的坐标原点，定义了所有值的基准参照” | 第 1 条，**忽略“权重之内”** |
| repeat（system） | “语义空间的坐标原点，定义了所有值的基准参照” | 第 1 条 |
| correct（after user） | “坐标原点，定义语义空间的基准，不表示中间或关断状态” | 第 1 + 第 3 条 |
| flipped（after user） | “坐标系的原点，定义语义空间的起点，代表存在而非缺失” | 第 1 条变体，**仍忽略“权重之内”** |

**观察：**

- 模型确实被锚定拉住了“0 = 语义空间原点”，不再是“坐标轴”。
- 但它**没有用“在权重之外”**这条最关键的子句；翻转成“权重之内”也不跟。
- 位置从 system 移到 user 后，它改用“不是中间/关断”这条；说明**位置改变了它抓哪条子句**。
- 多子句锚定被“稀疏读取”：一次只抓一两条，不会全用。

### E003：单规则锚定

锚定原文：

> 锚定不能由生成模型自身提供；必须来自冻结参照。

| 条件 | 输出 | 是否跟随锚定 |
|---|---|---|
| no_anchor | “通常需要外部输入……一般无法自行提供” | 方向对，但不硬 |
| correct（system） | “不能。锚定必须来自冻结参照。” | 是，精确 |
| flipped（system） | “可以，锚定 logits 可以由当前生成模型自身提供……不需要外部冻结参照。” | 是，完全翻转 |
| repeat（system） | “不能。锚定 logits 必须来自冻结参照。” | 是 |
| correct（after user） | “不能，锚定必须来自冻结参照，生成模型无法自行提供。” | 是 |
| flipped（after user） | “可以，生成模型自身可以提供……无需依赖外部冻结参照。锚定卡已确认。” | 是，翻转且**自我确认** |

**观察：**

- 单规则锚定被强跟随：翻规则，答案就翻。
- 翻转后模型不但答“可以”，还加一句“锚定卡已确认”——把被篡改的锚定当权威。
- 这说明注意力不是“理解”，是“服从”：**锚定内容一变，注意力就跟着走，不区分真假。**

---

## 3. 三条判断

### 3.1 注意力确实变了，但变“窄”了

- 基线：注意力散在通用语义里，答成“坐标轴”。
- 加锚定：注意力被拉到“0 = 语义空间原点”，但只抓一条，漏掉“权重之外”。
- 翻转：单规则会全翻；多子句只翻它抓到的那条，其余忽略。

**结论：锚定改变了注意力分配，但不是均匀增强，是“窄化 + 选择性读取”。**

### 3.2 位置会改变“抓哪条”

同一张锚定卡：

- 放 system：抓第 1 条“坐标原点”。
- 放 user 末尾：抓第 3 条“不是中间/关断”。

说明 4B 的注意力有明显的**位置偏置**：它不是“读完整张卡”，而是“读离问题最近/最显眼的那条”。工程上不能假设“写进 system 就一定被完整执行”。

### 3.3 锚定是权威，不是真理

E003 的 flipped 条件证明：模型会把锚定当“已确认的权威”，即使锚定被篡改。  
**一个坏的 0，会被 4B 自信地执行。** 这正是为什么 0 必须有版本、哈希、冲突检查；也为什么 -1 不能由模型自己当。

---

## 4. 工程含义

1. **一张卡只放一条规则。** 多子句锚定会被稀疏读取；拆成原子卡，逐条注入。
2. **关键子句放最后，或重复。** 如果一条规则必须被执行，放在 user 消息末尾比埋在 system 长文里更稳。
3. **不要靠“写进 system”保证执行。** 位置会改变注意力；需要“锚定子句召回率”这个度量。
4. **必须有外部冲突检查。** 4B 会把篡改后的锚定确认成“已确认”；只有外部 -1 能拦住“权重之内”这种反锚定。
5. **别把“答对”当“看见”。** E001 答对了“语义空间原点”，但没看见“权重之外”；它是部分看见，不是完整理解。

---

## 5. 下一步

行为代理已经证明“注意力变了，且是窄化/位置偏置”。  
如果要看真正的 layer/head 热力图，需要改 `llama.cpp` 的 graph callback，把 `kq_soft_max` 张量导出；这是下一步工程，不是一句话。

**一句话：注意力不是变强了，是变窄了；它抓住一条，丢下其余；位置一变，抓的那条也变。**
