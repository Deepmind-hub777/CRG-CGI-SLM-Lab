# ADR-0001 · 公开实验室 + 私有保险库

- **日期：** 2026-11-26
- **状态：** accepted（Milo 指示：仓库应该 public）
- **主张标签：** `[D]` 治理决定

---

## 1. 背景

四个人（Milo、豆包、Grok、学生）需要一个“场”：共享的规范、skills、代码、评测、失败记录。
这个实验可能失败；失败也要成为后人继续突破的基础。

同时，这个实验涉及：

- NAC 的学生数据、家长报告、学校合同；
- 教师轨迹与商业计划；
- API key、受限模型权重。

这些不能公开。

---

## 2. 决定

采用 **public lab + private vault** 双层结构：

| 层 | 放什么 | 放哪 |
|---|---|---|
| **Public lab** | SPEC、skills、代码、合成数据、评测脚本、失败日志、路线图、设计辩论 | 本仓库（public） |
| **Private vault** | 学生数据、家长报告、学校合同、真实教师轨迹、API key、受限权重、商业计划 | 私有仓库 / 私有云盘 |

**边界规则：**

1. 拿不准就放 private。
2. public 只放“愿意让全世界永久复制”的东西。
3. NAC 教务数据与研究数据物理分库。
4. 公开前先列“不能公开”的清单；公开不可逆。

---

## 3. 后果

**好处：**

- 学生、Grok、豆包都能读同一套规范；不用在聊天里反复同步。
- 失败记录可被后人复用；失败成为资产。
- 代码与评测可复现；PR 可审计。
- public 的约束会逼我们把话说清楚。

**代价：**

- 公开后无法真正撤回；fork/缓存/镜像可能留存。
- 竞争者可以看代码；护城河不在代码，在 0 轴、数据、治理与执行。
- 需要持续维护“公开/私有”边界，不能图省事。

---

## 4. 被否决的替代方案

| 方案 | 为什么不做 |
|---|---|
| 全 private | 学生与外部协作者无法读；失败无法成为公共资产 |
| 全 public | 学生数据/合同/密钥会泄漏；不可逆 |
| 只放代码，不放失败 | 失败变成轶事；后人无法从终点起跑 |
| 只放文档，不放可运行代码 | 无法复现；变成“故事会” |

---

## 5. 复审

- 每 3 个月复审一次边界。
- 任何“要不要公开某类数据”的争议，走 RFC；Milo 裁定。
- 如果 public 带来不可接受的风险，切回 private 的代价要提前写清楚。
