**最后更新：** 2026-11-26

## 1. 为什么 0 必须在权重之外

三句话：

1. **0 一旦可训练，就会漂移。** 梯度会把它拉向数据分布；数据变了，原点就变了。原点随数据走，等于没有原点。
2. **0 一旦由生成模型提供，就是自指。** 模型可以为自己任何输出找到一个“合理的原点”；自己批自己，永远通过。
3. **0 一旦和 -1 共用 adapter，就是软模型审软模型。** 生成与校验共享同一套偏差，校验只是复述。

所以：

> **+1 和 -1 可以训进权重；0 不能。**
> 权重学“回到原点”，不是“成为原点”。

---

## 2. 0 不是什么

| 常见误解 | 纠正 |
|---|---|
| 0 是“不输出/关断” | 0 是坐标原点；关断是 absence，不是 origin |
| 0 是“中间值/中性” | 0 不是三值里的中间档；它定义整个空间 |
| 0 是“零权重” | 三值量化里的 0 是零权重；三元算子的 0 是原点 |
| 0 是“系统提示词” | 提示词会随上下文漂；0 必须冻结、有哈希 |
| 0 是“一个更大的模型” | 更大的模型仍是 +1；它不能给自己提供原点 |

## 3. 三种实现

| 方案 | 是什么 | 成本 | 可审计性 | 适用 |
|---|---|---|---|---|
| **A. 冻结嵌入索引** | SQLite + sqlite-vec / FAISS；规范语料的向量索引，只读 | 低 | 高 | Qwen3-4B 默认 |
| **B. 冻结参考模型** | 一个小型、量化、冻结的参考模型，输出锚定 logits | 中 | 中 | 高风险场景 |
| **C. 规范语料 + 确定性规则** | 结构化条目 + 规则校验；可逐条引用 | 低 | 最高 | 安全、格式、术语 |

**建议：** 先 A + C；G2 校验失败再上 B。不要一上来堆三个锚定。

### 3.1 方案 A：冻结嵌入索引

- 输入：规范语料（术语表、定义、已验证轨迹的“结论句”）。
- 存储：SQLite + sqlite-vec；每条带 `id`、`text`、`source`、`version`、`hash`。
- 检索：top-k；返回 `anchor_id` 与相似度。
- 锚定 logits：把检索到的条目构造成“下一 token 的偏好分布”，或作为约束语法的候选集。
- 优点：端侧可跑、可离线、可审计。
- 缺点：语义覆盖有限；对长程推理的锚定弱。

### 3.2 方案 B：冻结参考模型

- 选一个比主模型更小、更稳、量化的模型（例如 1–2B），冻结，不训练。
- 用它的 logits 作为 \(a\)。
- 优点：语义连续，适合开放式生成。
- 缺点：双模型延迟；参考模型也有盲区；必须明确“参考模型不是 0，只是 0 的一个投影”。

> 关键区分：参考模型是 0 的**投影**，不是 0 本身。0 是坐标定义；参考模型是它在某个语料/任务上的近似。

### 3.3 方案 C：规范语料 + 确定性规则

- 术语、数字、格式、引用，用规则硬校验。
- 每条规则有 `rule_id`、版本、生效日期。
- 优点：可复现、可审计、可回滚。
- 缺点：覆盖窄；不适合“意义”层面的锚定。

## 4. 锚定对象

每个锚定必须是一个有身份的物件：

```json
{
  "anchor_id": "anchor-v0",
  "hash": "sha256:...",
  "source": "canonical corpus + frozen embeddings",
  "version": "2026-11-26",
  "owner": "Milo",
  "change_policy": "RFC only",
  "scope": "terminology + verified conclusions"
}
```

每条 trace 必须记录：

```json
{
  "anchor_id": "anchor-v0",
  "anchor_hash": "sha256:...",
  "beta": 0.6,
  "gamma": 0.3,
  "entropy": 1.42,
  "kl_to_anchor": 0.18,
  "gate": "G1",
  "top_k_hash": "..."
}
```

没有 `anchor_hash` 的评测结果，不算结果。

---

## 5. 0 的三条禁令

1. **不训练。** 0 不进入 optimizer；不建可训练的 anchor embedding。
2. **不自生成。** 锚定不能由当前生成模型产生；不能用“模型上一轮输出”当锚定。
3. **不随对话漂移。** 0 不因用户语气、角色扮演、长上下文而改变；改变只能走 RFC。

违反任何一条，就不是 0，只是另一个 +1。

---

## 6. 0 的更新

0 可以更新，但必须是**宪制事件**，不是训练事件：

1. 写 `proposals/rfc/RFC-000x-<slug>.md`。
2. 说明：改什么、为什么、影响哪些 gate、如何回滚。
3. Milo 批。
4. 新版本 + 新哈希；旧版本保留，可回滚。
5. 在所有 eval 上重跑 G1/G2；不能只跑“自己喜欢的例子”。

---

## 7. 锚定不是知识库

- 知识库回答“是什么”；锚定回答“以什么为原点”。
- 检索是 +1 的辅助；锚定是 0 的投影。
- 不要把 RAG 检索结果直接当 0；RAG 可以错、可以过时、可以被污染。
- 0 必须比 RAG 更稳定、更少、更可审计。

---

## 8. 端侧落地

| 设备 | 方案 | 说明 |
|---|---|---|
| 一加十二 24G/1T | A + C | SQLite + sqlite-vec；规则校验；Qwen3-4B Q4 |
| PC（训练） | A + C + 可选 B | 训练时 0 外置；不把 0 写进 adapter |
| 高风险场景 | B + C | 参考模型 + 规则双锚；仍由人终审 |

**不要**在手机上跑“双 4B 模型”做逐 token 锚定；延迟和温控会先崩。
